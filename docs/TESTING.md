# راهبرد و گزارش تست‌های خودکار (`docs/TESTING.md`)

تمامی لایه‌های سامانه با تست‌های خودکار واقعی روی **PostgreSQL واقعی** (بدون شبیه‌سازی جعلی لایهٔ دیتابیس) پوشش داده شده‌اند.

---

## ۱. سطوح چهارگانهٔ تست

### ۱.۱ تست‌های واحد (`npm run test`)

- اجرا با `Vitest 5` روی بستهٔ `@food/shared` (`25` تست):
  - الگوریتم رقم کنترلی کد ملی، اعتبارسنجی شبا، تبدیل ریال/تومان و ارقام فارسی/عربی.
  - محاسبات تاریخ شمسی و منطقهٔ زمانی `Asia/Tehran` (شامل لبه‌های نیمه‌شب).
  - ماتریس مجوزهای RBAC و سلسله‌مراتب نقش‌ها.

### ۱.۲ تست‌های یکپارچهٔ PostgreSQL (`npm run test:integration`)

- اجرا روی یک نمونهٔ واقعی PostgreSQL (`embedded-postgres` در محیط محلی و کانتینرهای **PostgreSQL 16 و PostgreSQL 15** در GitHub Actions CI) شامل **۸ فایل و ۱۳۲ سناریوی تست**:
  - `schema.test.ts` (۳۱ تست): قیدهای `CHECK`، ایندکس یکتای جزئی رزرو چندغذایی، تریگرهای Append-Only دفتر کل و ممیزی، ممنوعیت `DELETE` فیزیکی و مجوزهای واقعی نقش محدود `food_app`.
  - `auth.test.ts` (۳۱ تست): ورود دانشجو/کارکنان/کارمند، مهاجرت خودکار `PBKDF2` به `Argon2id`، کوکی `__Host-sid`، محافظت CSRF، هدرهای امنیتی و CSP، قفل تلاش ناموفق `(شناسه + IP)`، کپچا و عدم نشت کد ملی یا هش رمز.
  - `rbac.test.ts` (۱۴ تست): ماتریس کامل نقش × مسیر، تفکیک وظایف `SuperAdmin` و `Finance` و مسدودسازی ارتقای دسترسی.
  - `import.test.ts` (۱۶ تست): پیش‌نمایش و ثبت تراکنشی اکسل، رد فایل‌های دارای ماکرو/حجیم، تعارض کد ملی، همگام‌سازی کامل، قفل هم‌زمانی تأیید و بازگردانی (Undo) آخرین دسته.
  - `business.test.ts` (۳۲ تست): رزرو چندغذایی، رقابت ۵۰ درخواست هم‌زمان برای ظرفیت ۱۰، زیرساخت لغو و بازپرداخت دسته‌ای، پرداخت مستقیم درگاه زرین‌پال، کف ۱۰٬۰۰۰ ریال شاپرک، تکمیل ظرفیت حین حضور در درگاه (`SAVEPOINT` + انتقال مابقی به اعتبار کیف پول)، حالت `NeedsReview` و آشتی‌سازی، اسکن و تحویل هم‌زمان QR/کد ۸ کاراکتری و همگام‌سازی آفلاین.
  - `worker.test.ts` (۲ تست): اجرای تمام jobهای پس‌زمینه با نقش `food_app`، ثبت در `job_runs` و اثبات عدم اجرای تکراری بین ۲ پردازشگر هم‌زمان با `pg_try_advisory_lock`.
  - `upload.test.ts` (۴ تست): تغییر اندازهٔ تصویر با `sharp` به ≤۱۲۰۰px، حذف متادیتای EXIF، رد فایل‌های جعلی با بررسی بایت جادویی، مسیر جایگزین امن بدون `sharp` (پردازنده‌های فاقد `AVX2`) و هدرهای کش `/uploads`.
  - `pwa.test.ts` (۲ تست): سرو صحیح مانیفست فارسی/RTL، آیکن‌ها، `sw.js` با `Cache-Control: no-cache`، دارایی‌های هش‌شده با `immutable` و SPA fallback در حالت `SERVE_STATIC=true`.

### ۱.۳ آزمون بار و رقابت هم‌زمانی (`npm run loadtest`)

- اسکریپت `scripts/loadtest.ts` با `autocannon` و PostgreSQL واقعی سه معیار را اجرا و راستی‌آزمایی می‌کند:
  1. ۵۰۰ درخواست هم‌زمان خواندن منوی دانشجو (`GET /api/v1/me/menu`) بدون خطا.
  2. ۵۰ درخواست هم‌زمان تسویه روی وعده‌ای با ظرفیت ۱۰ (`موفق = ۱۰`، `رد ظرفیت = ۴۰`، `reserved_count = 10` و تراز دقیق صفر در دفتر کل).
  3. ۳۲ ورود هم‌زمان کارکنان با هش سنگین `Argon2id` بدون خطا.

### ۱.۴ آزمون سرتاسری مرورگر (`npm run test:e2e`)

- پیکربندی‌شده با `@playwright/test` در `apps/web/playwright.config.ts` و `apps/web/e2e/app.spec.ts` (شبیه‌سازی موبایل Pixel 7 با زبان فارسی و زمان تهران: ورود دانشجو ← انتخاب دو غذا در یک وعده ← ثبت قطعی ← بررسی نبود دکمهٔ لغو ← نمایش بلیط تمام‌صفحه و کد ۸ کاراکتری بدون `R-` ← ورود اپراتور سلف و تحویل غذا با کد ۸ کاراکتری).
- این آزمون در پایپ‌لاین GitHub Actions CI پس از نصب مرورگر `chromium` به طور خودکار اجرا می‌شود.
