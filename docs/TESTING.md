# راهبرد و گزارش تست‌های خودکار (`docs/TESTING.md`)

تمامی لایه‌های سامانه با تست‌های خودکار واقعی روی **PostgreSQL واقعی** (بدون شبیه‌سازی جعلی لایهٔ دیتابیس) پوشش داده شده‌اند.

---

## ۱. سطوح چهارگانهٔ تست

### ۱.۱ تست‌های واحد (`npm run test`)

- اجرا با `Vitest 5` شامل **۴ فایل و ۳۳ سناریوی تست**:
  - `packages/shared/test/domain.test.ts` (۱۵ تست): الگوریتم رقم کنترلی کد ملی، اعتبارسنجی شبا، تبدیل ریال/تومان و ارقام فارسی/عربی.
  - `packages/shared/test/time-and-rbac.test.ts` (۱۱ تست): محاسبات تاریخ شمسی و منطقهٔ زمانی `Asia/Tehran`، ماتریس مجوزهای RBAC، سلسله‌مراتب نقش‌ها و آزمون عدم واگرایی `docs/RBAC.md`.
  - `apps/web/test/offline-delivery.test.ts` (۴ تست): اسکن آفلاین، صف `IndexedDB` (`fake-indexeddb`)، جلوگیری از تکرار محلی، دسته‌بندی `<=50`، همگام‌سازی و تشخیص تعارض `OfflineConflict`.
  - `apps/api/test/unit/deploy-backup.test.ts` (۳ تست): رمزنگاری `backup.sh` با کلید عمومی، فایل `.sha256`، حذف بکاپ‌های قدیمی‌تر از ۱۴ روز، رد کلید خصوصی روی سرور و تمرین بازیابی `restore-drill.sh`.

### ۱.۲ تست‌های یکپارچهٔ PostgreSQL (`npm run test:integration`)

- اجرا روی یک نمونهٔ واقعی PostgreSQL (`embedded-postgres` در محیط محلی و کانتینرهای **PostgreSQL 16 و PostgreSQL 15** در GitHub Actions CI) شامل **۸ فایل و ۱۳۷ سناریوی تست**:
  - `schema.test.ts` (۳۱ تست): قیدهای `CHECK`، ایندکس یکتای جزئی رزرو چندغذایی، جدول `reservation_reminders`، تریگرهای Append-Only دفتر کل و ممیزی، ممنوعیت `DELETE` فیزیکی و مجوزهای واقعی نقش محدود `food_app`.
  - `auth.test.ts` (۳۲ تست): ورود دانشجو/کارکنان/کارمند، اعلان ورود از دستگاه جدید و ثبت آخرین ورود قبلی، مهاجرت خودکار `PBKDF2` به `Argon2id`، کوکی `__Host-sid`، محافظت CSRF، هدرهای امنیتی و CSP، قفل تلاش ناموفق `(شناسه + IP)`، کپچا و عدم نشت کد ملی یا هش رمز.
  - `rbac.test.ts` (۱۵ تست): اثبات خودکار پوشش ۱۰۰٪ مسیرهای ثبت‌شده زیر `/api/v1/*`، ماتریس کامل هر مسیر × هر نقش، آزمون نگهبان سراسری **Fail-Closed** برای مسیر بدون مجوز ثبت‌شده، تفکیک وظایف `SuperAdmin` و `Finance` و چرخهٔ کامل مدیریت `Employee` (ساخت، ویرایش، غیرفعال‌سازی، ریست رمز و ایمپورت با خروجی یک‌بارمصرف).
  - `import.test.ts` (۱۶ تست): پیش‌نمایش و ثبت تراکنشی اکسل، رد فایل‌های دارای ماکرو/حجیم، تعارض کد ملی، همگام‌سازی کامل، قفل هم‌زمانی تأیید و بازگردانی (Undo) آخرین دسته.
  - `business.test.ts` (۳۳ تست): رزرو چندغذایی، رقابت ۵۰ درخواست هم‌زمان برای ظرفیت ۱۰، زیرساخت لغو و بازپرداخت دسته‌ای، پرداخت مستقیم درگاه زرین‌پال، کف ۱۰٬۰۰۰ ریال شاپرک، تکمیل ظرفیت حین حضور در درگاه (`SAVEPOINT` + انتقال مابقی به اعتبار کیف پول)، حالت `NeedsReview` و آشتی‌سازی، اسکن آنلاین، مانیفست آفلاین بدون توکن خام و تعارض دو دستگاه آفلاین (`OfflineConflict`).
  - `worker.test.ts` (۴ تست): اجرای تمام jobهای پس‌زمینه (از جمله `send-meal-reminders` هر ۱۰ دقیقه با منطقهٔ زمانی تهران و جداسازی موبایل/بدون موبایل) با نقش `food_app`، ثبت در `job_runs` و اثبات عدم اجرای تکراری بین ۲ پردازشگر هم‌زمان با `pg_try_advisory_lock`.
  - `upload.test.ts` (۴ تست): تغییر اندازهٔ تصویر با `sharp` به ≤۱۲۰۰px، حذف متادیتای EXIF، رد فایل‌های جعلی با بررسی بایت جادویی، مسیر جایگزین امن بدون `sharp` (پردازنده‌های فاقد `AVX2`) و هدرهای کش `/uploads`.
  - `pwa.test.ts` (۲ تست): سرو صحیح مانیفست فارسی/RTL، آیکن‌ها، `sw.js` با `Cache-Control: no-cache` و بررسی محتوای تولیدشدهٔ `sw.js` برای عدم کش پاسخ‌های API، دارایی‌های هش‌شده با `immutable` و SPA fallback در حالت `SERVE_STATIC=true`.

### ۱.۳ آزمون بار و رقابت هم‌زمانی (`npm run loadtest` — مستند در `docs/PERF.md`)

- اسکریپت `scripts/loadtest.ts` روی PostgreSQL واقعی ۵ سناریوی کامل را اجرا و راستی‌آزمایی می‌کند:
  1. پیش‌نمایش و ثبت نهایی فایل اکسل ۵٬۰۰۰ و ۲۰٬۰۰۰ دانشجو (`UNNEST` دسته‌ای و `HMAC` موازی).
  2. رقابت هم‌زمان ۳۰۰ دانشجو روی یک وعده با ظرفیت ۲۰۰ (`۲۰۰` رزرو موفق، `۱۰۰` رد ظرفیت، `reserved_count = 200`، موجودی منفی صفر، تراز دقیق صفر دفتر کل و `p95 < 1500ms`).
  3. ۱٬۰۰۰ ورود هم‌زمان دانشجو + ۱۰۰ ورود هم‌زمان کارکنان با هش سنگین `Argon2id`.
  4. ۲٬۰۰۰ درخواست هم‌زمان خواندن منوی دانشجو (`GET /api/v1/me/menu`) بدون خطا.
  5. ۲۰ بازگشت هم‌زمان callback زرین‌پال برای یک پرداخت واحد (`دقیقاً ۱ تسویه` در دفتر کل).

### ۱.۴ آزمون سرتاسری مرورگر و اسکرین‌شات (`npm run test:e2e` و `npm run screenshots`)

- پیکربندی‌شده با `@playwright/test` در `apps/web/playwright.config.ts` و `apps/web/e2e/app.spec.ts` روی شبیه‌ساز موبایل Pixel 7 (زبان فارسی، چیدمان RTL و منطقهٔ زمانی `Asia/Tehran`) در دو سناریوی جامع:
  1. ورود دانشجو ← انتخاب چند غذا در یک وعده ← تسویه با اعتبار ← بررسی نبود دکمهٔ لغو ← نمایش بلیط تمام‌صفحه و کد ۸ کاراکتری بدون `R-` ← ورود اپراتور سلف و تحویل آنلاین غذا.
  2. چرخهٔ کامل عملیاتی: ورود معاونت دانشجویی و ایمپورت فایل `.xlsx` ← ورود مدیر تغذیه و افزودن غذا به کتابخانه ← ورود دانشجوی تازه‌ایمپورت‌شده و رزرو دو غذا از طریق درگاه پرداخت آزمایشی (`sandbox`) ← تحویل آنلاین بلیط اول + قطع شبکه با `context.setOffline(true)`، اسکن آفلاین بلیط دوم، رد اسکن تکراری آفلاین، اتصال مجدد و همگام‌سازی صف با سرور ← بررسی گزارش مدیریت.
- اسکریپت `scripts/screenshots.ts` (`npm run screenshots`) در محیط دارای Chromium هفت اسکرین‌شات واقعی موبایل و دسکتاپ RTL را در `docs/screenshots/` ثبت می‌کند و در GitHub Actions CI به‌صورت آرتیفکت `ui-screenshots-rtl` بارگذاری می‌شود.
- **یادداشت محیط سندباکس محلی:** در محیط سندباکس ساخت، دستور `npx playwright install chromium` به دلیل مسدود بودن فایروال خروجی به `cdn.playwright.dev:443` (`ECONNRESET`) قابل دانلود نیست؛ هیچ اسکرین‌شات جعلی ساخته نشده و اجرای واقعی در کار `e2e-playwright` پایپ‌لاین GitHub Actions انجام می‌شود.
